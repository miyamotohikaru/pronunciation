# tools/model/distill — 「実際に言った音」を出す小型音素モデル（蒸留）

学習者が**実際に発音した音**を、フレームごとの音素確率（phone posteriorgram）で返す小型モデル。
ブラウザで動かすために作った（onnxruntime-web 用、23.1M パラメータ、int8w で 24.2 MB）。

今の小型モデル vb223/whisper-base-en-phoneme-ctc（MIT）は、L2 音声を「正しい音素列」で学習している。
そのため典型的な誤りを直して出してしまう（sink の s を θ と出す、挿入母音が消える）。
ここでは、聞こえたとおりに出す大型モデル facebook/wav2vec2-lv-60-espeak-cv-ft
（Apache-2.0、316M、多言語 IPA）を教師にして、
vb223 と同じ whisper base.en エンコーダに知識を移した。

スクリプトはこのフォルダ、データ・チェックポイント・ログ・書き出しは `.work/distill/`（コミットしない）。
作業記録は `.work/distill/LOG.md`。

## 結果の要約

- 配布用は `student.int8w.onnx`（重みだけ int8、計算は fp32）で **24.2 MB**。
  PyTorch との差は greedy PER 0.6%、onnxruntime-web 1.30（WASM）と Python の差は確率で 1e-5 以下。
- CPU の速さ（M4 Pro）。
  WASM 1 スレッドで 3 秒の音声が 131 ms、8 秒が 373 ms。4 スレッドなら 37 ms / 122 ms。
  ネイティブ ORT では 1 スレッド 64 / 181 ms。スマホではこの 2〜4 倍を見込む。
- 4 bit 版（`student.q4.onnx`、15.7 MB）も作ったが、fp32 との greedy PER が 5% 開くので、配布は int8w にした。
- 教師との一致（学習に使っていない話者、粗い記号での PER、低いほど教師に近い）は、
  LibriSpeech .058（vb223 .257）、GLOBE .100（.315）、speechocean762 .233（.378）、日本語なまりの GLOBE 話者 .116（.335）。
- 最小対テスト（macOS `say`、1152 本）で「言った音を出せた」割合は、
  英語の声の正しい発音 .744、英語の声の誤り .800、日本語の声のカタカナ読み .939。
  教師は .575 / .648 / .895、vb223 は .702 / .744 / .766。
- Speech Accent Archive の日本語話者 15 名（人手の精密 IPA）では、
  人手との PER は 教師 .225、生徒 .252、vb223 .337。
  人手が「正規形と違う」と書いた置き換えのうち、生徒は 32% を再現し 47% を正規形に直した（教師 24% / 59%、vb223 26% / 37%）。
  挿入母音は 生徒 57%、教師 46%、vb223 37% を拾った。

## しくみ

### 教師と生徒

| | 教師 | 生徒 |
|---|---|---|
| モデル | wav2vec2-lv-60-espeak-cv-ft（316M） | whisper base.en エンコーダ 6 層 + MLP ヘッド（23.1M） |
| 出力 | 392 トークン（多言語 espeak IPA、声調付き） | 79 トークン（下の縮約 IPA、0 番が CTC blank） |
| 入力 | 16 kHz 波形 | whisper log-mel [1, 80, L]（30 秒に詰めない） |
| フレーム | 20 ms | 20 ms（50 fps） |

生徒の初期値は vb223 から取った。
エンコーダと、ヘッドの隠れ層 2 段（512→2048→1024）はそのまま使う。
出力層は新しい 79 行で、ARPAbet に対応がある音素は vb223 の該当行（強勢違いは平均）から始める。

### フレームの合わせ方

- whisper の mel は hop 160・center=True なので、エンコーダの出力フレーム i は音声のサンプル 320·i が中心になる。
- wav2vec2 のフレーム i は [320·i, 320·i+400) を見るので、中心は 320·i+200 になる。
- そこで教師の入力の前後に 200 サンプルの無音を足した。
  こうすると教師フレーム i の中心も 320·i になり、生徒フレーム i とぴったり重なる。
  生徒のフレーム数 M = ceil((n_samples // 160) / 2) に切りそろえる。
- 確認として、教師と vb223 初期値の「非 blank 質量」の相関を取った。
  ずれ 0 が最大になる（−1 で 0.92、+1 で 0.81）。
- 4 秒未満のクリップは、教師にだけ前後 0.5 秒（25 フレームちょうど）の無音を足してから、その分を捨てる。
  単語単体での教師の正答が 0.757 から 0.80 に上がった。

### 音素セット（79 個）

教師の 392 トークンを次の方針で 79 個にまとめた。
生徒の目標は、まとめた先ごとに教師の確率を**足し合わせた**分布（周辺分布）。
確率の量は失わず、まとめた音どうしの区別だけがなくなる。

1. 英語と、日本語なまりの英語で教師が実際に使う音は残す（ɾ、ɯ、ɕ、ts、ɸ、e、o、a、長母音など）。
2. アプリに要らない区別は外す。声調（数字）、子音の長音、口蓋化 ʲ、
   中国語式の有気音表記（`th` `kh` `ph` は有気の t k p で、θ ではない）、歯音・鼻音化などの補助記号。

Common Voice 本体は HF から消えていたので、Common Voice 由来で CC0 の GLOBE を使った。
GLOBE V1 の訛りメタデータを HTTP の range 読みだけで全 108 shard 分読み、話者ごとにまとまっている row group だけを取り出した。

- LibriSpeech と speechocean762 は ±10% の速さ（0.9/1.0/1.1、確率 .2/.6/.2）を、教師にかける**前**に適用した。
  こうすると教師のラベルが速さの変わった音声とずれない。
- 雑音・残響などは学習時にその場でかける（`augment.py`）。
  白・ピンク・ブラウン雑音、人の声のざわめき（他の発話を 3〜6 本重ねる）、ハム、
  合成残響（RT60 0.15〜0.8 秒、直接音はずらさない）、帯域制限、8 kHz 電話（μ-law あり）、イコライザ、音量 −30〜−1 dBFS、まれにクリップ。
  教師の目標は、きれいな音声に対するもののままにする（生徒は雑音の下でも同じ答えを出すように学ぶ）。
- 時間マスクは使わない。
  前後の文脈から音を推測するくせ（＝自動修正）を育てないため。
  代わりに 50% の確率で 1〜12 秒の短い切り出しを使い、局所的な音響で決めるように促した。

### Kokoro の合成音声と「注入した誤り」

日本語なまりの実音声は、許諾の合う形ではほとんど手に入らなかった（下の「未解決」）。
そこで Kokoro-82M（Apache-2.0）で英語を読ませ、学習者に典型的な誤りを音素列に入れて合成した（`kokoro_gen.py`）。

- 英米の声 25 種、日本語の声 4 種、中・印・西・仏・伊・葡の声 18 種。
  評価用に 6 種（am_michael、bf_emma、jf_nezumi、zf_xiaoxiao、zm_yunxia、pm_santa）は学習に使っていない。
- 誤りの種類は ɹ→l/ɾ、l→ɹ/ɾ、θ→s/t/f、ð→z/d、v→b、f→ɸ/h、si→ʃi/ɕi、æ/ʌ/ɑ→a、ɪ↔i、子音のあとの母音挿入。
  日本語の声には、全体をカタカナ読みに変える型もある。
- 目標は基本的に教師だが、**確実に音になっている注入箇所だけ**は、合成した音素を正解として上書きする。
  確実な注入箇所は ɹ↔l、v→b、θ→s/t/f、ð→z/d、s→ʃ/ɕ、f→h と挿入母音。
  上書きでは、合成した音素列を教師の確率に CTC で強制アライメントして教師の時間位置を使い、そのフレームの質量の 0.8 を正解の音素に置く（`dataset.truth_target`）。
  教師が「berry good」を「very good」と聞くような語彙のくせを、生徒に引き継がせないため。
- 教師は注入した置き換えの 55% しか聞き取らない（ɹ→l .79、v→b .85、ð→z .75 だが、ɹ→ɾ .07、f→ɸ .0）。
  ɾ と ɸ は Kokoro の英語の声ではっきり音にならないようなので、上書きには使わない。

### 損失と学習

- フレームごとの KL(教師 ‖ 生徒)（τ = 1）＋ 0.2 × CTC（教師の greedy 列、上書き箇所はその音素）。
- AdamW、エンコーダ lr 1e-4〜1.5e-4、ヘッド 3e-4〜5e-4、warmup のあと cosine、grad clip 5。
- 1 ステップは約 160〜200 秒分の音声（1 秒刻みの長さバケツ、バケツごとにバッチ数を固定）。
  MPS は形ごとにグラフを作り直すので、形を固定しないと 1 ステップ 20〜50 秒かかった。
  固定したあとは実時間の 250〜450 倍で学習できる。
- r1: vb223 から 4000 ステップ（GLOBE なし）。
  r2: r1 から全データ。配分（音声時間の割合）は LibriSpeech .27、speechocean .15、GLOBE .27（東アジア系 .13）、Kokoro .30（日本語の声 .14）。
  r2 は 3000 ステップ目で止め（MPS のメモリ膨張）、r3 として 2000 ステップの低い lr で仕上げた（合計 9000 ステップ、約 340 時間分の音声を処理）。
- 最後に blank の出力バイアスを −1.0 した（`ckpt/final/student.pt`、理由は「書き出し」）。

## 評価

評価にはどれも学習に使っていない話者・声だけを使った。
「粗い記号」は r 音色を母音＋ɹ に分け、ə/ʌ/ɐ、iː/i、ɑː/ɑ/a などを同じ組にし、同じ記号の連続を 1 つにしたもの（`eval_saa.norm`）。
vb223（ARPAbet）と生徒（IPA）を同じ土俵で比べるために使う。

### 1. 教師そのもの（LibriSpeech dev-clean/other、618 発話、CMUdict の正規形と比較）

| 音 | recall | precision | 主な取り違え |
|---|---|---|---|
| θ | .878 | .938 | ð 9%（with など辞書側の揺れ） |
| ð | .977 | .970 | 脱落 1% |
| ɹ | .866 | .831 | 脱落 4.5%、ɚ などへの吸収 4.8% |
| v | .986 | .993 | f .3%、b .1% |
| æ | .794 | .686 | and/that の弱形（ɐ/ə） |

全体の PER は 13.1%（弾音化や辞書の揺れを含む）。
母語話者の θ ð ɹ v は信頼できる。
Kokoro の母語音声でも θ は正しく出たので、Samantha の「s ɪ n k」は macOS の声の問題だった。

## 書き出し（ONNX）

`.work/distill/export/`（`export_onnx.py` で作り直せる）。

| ファイル | 大きさ | fp32 との一致（argmax / greedy PER） | ネイティブ CPU 1 スレッド 3 秒 / 8 秒 | 4 スレッド | WASM 1 スレッド | WASM 4 スレッド |
|---|---|---|---|---|---|---|
| `student.int8w.onnx`（**配布用**） | 24.2 MB | .998 / .006 | 64 / 181 ms | 18 / 50 ms | 131 / 373 ms | 37 / 122 ms |
| `student.q4.onnx`（4 bit、選択肢） | 15.7 MB | .982 / .050 | 50 / 142 ms | 15 / 42 ms | 185 / 393 ms | 42 / 128 ms |
| `student.fp32.onnx`（基準） | 95.4 MB | 1 / 0 | 65 / 183 ms | 18 / 50 ms | 167 / 381 ms | |
| `student.int8.onnx`（動的 int8、参考） | 29.1 MB | .993 / .018 | 37 / 99 ms | 8 / 24 ms | | |
| `student.fp16.onnx`（参考） | 47.7 MB | 1.000 / .0005 | 92 / 198 ms | 22 / 61 ms | | |

計測は M4 Pro。
ネイティブは onnxruntime 1.23（Python）、WASM はアプリと同じ onnxruntime-web 1.30 を Node で動かした。
- 入出力はアプリの vb223 版と同じ。
  `mel` [1, 80, L]（実音声の whisper log-mel、30 秒に詰めない）→ `log_probs` [1, ceil(L/2), 79]（log-softmax 済み）。
  50 フレーム/秒、出力フレーム i は音声のサンプル 320·i が中心、blank は 0 番。最長 30 秒（1500 フレーム）。
- int8w は、アプリの `tools/model/export/quantize_weights.py` と同じ形式にした。
  MatMul・Conv の重みと位置埋め込みを、チャンネルごとの対称 int8 ＋ DequantizeLinear で持つ。
  読み込み時にセッション設定 `session.disable_quant_qdq=1` を付けると、重みを一度 fp32 に戻して計算する。
  WASM と Python の出力差は確率で 8.8e-6、argmax は完全一致。
- 位置埋め込みは書き出し時に fp32 の Constant（3 MB）になっていたので、int8 の initializer に変えてから量子化した。
- blank の出力バイアスを −1.0 した（`ckpt/final/student.pt`）。
  短い音や弱い母音を拾いやすくする補正で、どの評価セットでも教師との一致が上がった。
  モデルに焼き込み済みなので、デコード時に重ねてかけない。
- `metadata.json` に語彙、blank、フレームの決まり、各ファイルの照合結果と速さを書いた。

## ラウンド 4：æ/ʌ/ɑ（hat/hut/hot）と V/B

教材に hat/hut/hot と V/B の単元があるので、生徒の弱点だったこの 2 つを狙って追加で学習した。
結果は `ckpt/final_r4/student.pt`、配布用は `export/student_r4.int8w.onnx`（24.2 MB）。
既存の `student.int8w.onnx` は上書きしていない。

### 教師はこれらの音をどこまで信用できるか

- LibriSpeech の普通の文では信用できる（æ .79、ʌ .97/.81、ɑː .65、v .99、b .995）。
- Kokoro で音を指定して作った最小対（正解が作り方から決まる）では弱い。
  単語単体の母音は、正しい発音でも .38〜.62 しか当たらない（外国語の a や ɑ にする）。
  v→b の置き換えは単体 .92 だが、「seven days」のような句では .70（26% を v に直す）。
- そこで、テストする 1 音だけ正解を作り方から与え、残りは教師に従わせた（`kokoro_pairs.py`）。
  米英 26 声で、母音語 120 と v/b 語 55、v を含む句 18 を用意した。
  正しい発音と、置き換えた発音（æ→ʌ/ɑ、ʌ→æ/ɑ、ɑ→æ/ʌ/o、v→b、b→v）を作り、計 4732 本。
  `say` テストの語と、very は学習に入れていない。
- 作り方どおりに音が出ていない型は捨てた（634 本）。
  英語の声に a を言わせると æ に聞こえ、英国の声の hot を ʌ で言わせると ɒ に聞こえるため。
- 学習は r3 から 1500 ステップ。
  最小対を 12%、注目する音（æ ʌ ɑː ɑ ɒ a o ɔ v b など）のフレームの KL を最大 3 倍に重み付けした。
  最後に、前回と同じ基準で blank を −1.0 補正した。

- 不採用の候補（r5b、b=0.5）は `ckpt/final_r5b_b05` と `export_r5b_b05/` に移して残した。

## 未解決・注意

- **日本語なまりの実音声が少ない。**
  許諾の合う学習用のものは見つからなかった（GLOBE では 7 名・21 発話だけで、全部評価に回した）。
  日本語らしさは Kokoro の合成と、L1 中国語の speechocean762、東アジア系の GLOBE で補っている。
  評価も、SAA（15 名、NC）、EdAcc（1 名、SA）、GLOBE（7 名）と小さい。
- **教師の弱点は生徒にも残る。**
  SAA の日本語話者で、人手が書いた置き換えの約半分を、生徒はまだ正規形に直す（教師よりは少ない）。
  単語単体の ʌ/æ は全モデルが苦手（say の hut/cut で生徒 .15、vb223 .46）。
  v/b の誤り（berry など）は vb223 のほうが拾う（.89 対 .79）。
  「berry good」のような語彙のくせは、教師から 18% ほど残っている。
- **会話音声は一致が低い**（EdAcc で教師との PER .32〜.36）。
  学習データは読み上げだけ。
- int8w は onnxruntime-web 1.30 の WASM で動くことと数値を確認した。
  WebGPU とスマホ実機ではまだ測っていない。
- 4 bit は、量子化を意識した学習（QAT）をすれば使える可能性がある。
  今回は精度を優先して int8w にした。
- 共有マシンの注意点が 2 つある。
  MPS は形ごとのキャッシュをため込むので、`torch.mps.empty_cache()` と `PYTORCH_MPS_HIGH_WATERMARK_RATIO` が要る。
  一時 12 GB まで膨らんだ。
  また zsh の BG_NICE で、裏で起動したジョブは nice 5 になり、macOS のアイドル時処理に負けて 10 倍以上遅くなる。
  裏で回すときは `unsetopt BG_NICE` してから起動する。
- macOS `say` の音声は評価専用。学習には使っていない。
